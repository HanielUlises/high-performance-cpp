## Definition

Computational mathematics is the study of algorithms for mathematical objects — polynomials,
integers, matrices, algebraic structures — with cost measured in operations of the underlying
algebra rather than in machine cycles.

<Definition title="Arithmetic complexity">
Fix a ring $R$ and count only ring operations, each at unit cost. The *arithmetic complexity*
of a computation is the minimum number of such operations over all algorithms computing it.
Bounds in this model are independent of the representation of elements, and translate to a
machine cost by multiplying by the cost of an operation in $R$.
</Definition>

## Motivation

Two distinct questions are addressed by the same body of theory.

The first is exactness. Some computations must be exact: determining whether a matrix is
singular, deciding the sign of a geometric predicate, verifying an algebraic identity, or
computing with polynomials whose coefficients must not drift. Floating-point arithmetic
answers none of these reliably, and the alternative is arithmetic in $\mathbb{Q}$,
$\mathbb{Z}$, or $\mathbb{Z}/p\mathbb{Z}$, where the cost model is the one above.

The second is structure. Fast algorithms — Karatsuba, Strassen, the fast Fourier transform —
are algebraic identities that reduce the operation count below the obvious bound. Whether
they are worth using is a question about their constants, their stability, and the size at
which the asymptotic advantage overcomes them.

## Formal formulation

The fundamental reductions are between problems, and the reductions are cheap.

Polynomial multiplication of degree $n$ reduces to the discrete Fourier transform of length
$2n$, since the DFT diagonalises convolution:

$$
\widehat{(f \cdot g)} = \hat{f} \odot \hat{g}, \qquad
f \cdot g = \mathrm{DFT}^{-1}\big( \mathrm{DFT}(f) \odot \mathrm{DFT}(g) \big),
$$

giving $\Theta(n \log n)$ operations against $\Theta(n^2)$ for the direct method.

Karatsuba's identity splits a product into three half-sized products rather than four:

$$
(a_1 x + a_0)(b_1 x + b_0) = a_1 b_1 x^2 + \big((a_1 + a_0)(b_1 + b_0) - a_1b_1 - a_0b_0\big)x + a_0 b_0,
$$

giving $T(n) = 3T(n/2) + \Theta(n)$ and $T(n) = \Theta(n^{\log_2 3}) = \Theta(n^{1.585})$.

Strassen's identity does the same for $2 \times 2$ block matrix multiplication, using seven
block products instead of eight:

$$
T(n) = 7T(n/2) + \Theta(n^2) \;\Rightarrow\; T(n) = \Theta(n^{\log_2 7}) = \Theta(n^{2.807}).
$$

The exponent of matrix multiplication, $\omega = \inf\{c : \text{MM in } O(n^c)\}$, is known
to satisfy $2 \le \omega < 2.372$, with the upper bounds below Strassen's obtained by methods
whose constants make them impractical.

Modular arithmetic supplies the standard technique for controlling coefficient growth: compute
modulo several primes and reconstruct by the Chinese remainder theorem.

<Theorem title="Chinese remainder">
For pairwise coprime $m_1, \dots, m_k$ with $M = \prod m_i$, the map
$$
\mathbb{Z}/M\mathbb{Z} \to \prod_i \mathbb{Z}/m_i\mathbb{Z}, \qquad
x \mapsto (x \bmod m_1, \dots, x \bmod m_k)
$$
is a ring isomorphism. A computation whose result is bounded in absolute value by $M/2$ may
therefore be performed independently modulo each $m_i$ and reconstructed.
</Theorem>

The practical value is that each modular computation uses machine-word arithmetic and the
$k$ computations are independent, hence embarrassingly parallel.

## C++ representation

Exact rational arithmetic with a normalising invariant:

```cpp
#include <cstdint>
#include <numeric>
#include <stdexcept>

namespace hpc {

// Invariant: denominator > 0 and gcd(|numerator|, denominator) == 1.
class rational {
public:
    constexpr rational(std::int64_t p = 0, std::int64_t q = 1) : num_{p}, den_{q} {
        if (q == 0) { throw std::domain_error{"zero denominator"}; }
        if (q < 0) { num_ = -num_; den_ = -den_; }
        const std::int64_t g = std::gcd(num_ < 0 ? -num_ : num_, den_);
        if (g > 1) { num_ /= g; den_ /= g; }
    }

    constexpr std::int64_t numerator() const noexcept { return num_; }
    constexpr std::int64_t denominator() const noexcept { return den_; }

    constexpr rational operator+(const rational& r) const {
        return rational{num_ * r.den_ + r.num_ * den_, den_ * r.den_};
    }

    constexpr rational operator*(const rational& r) const {
        return rational{num_ * r.num_, den_ * r.den_};
    }

    constexpr bool operator==(const rational&) const = default;

private:
    std::int64_t num_;
    std::int64_t den_;
};

}  // namespace hpc
```

The type satisfies `Field` from [Algebra](/docs/mathematics/algebra) on the subset of values
where no intermediate overflows, and the qualification is the entire practical difficulty:
exact rational arithmetic on unbounded integers is a field, and on `int64_t` it is a partial
one.

Modular arithmetic with the modulus as a template parameter, so that the reduction is a
constant:

```cpp
#include <cstdint>

namespace hpc {

template <std::uint64_t P>
class modular {
public:
    constexpr explicit modular(std::uint64_t v = 0) noexcept : v_{v % P} {}

    constexpr modular operator+(modular r) const noexcept {
        return modular{v_ + r.v_};
    }

    constexpr modular operator*(modular r) const noexcept {
        return modular{static_cast<std::uint64_t>(
            (static_cast<__uint128_t>(v_) * r.v_) % P)};
    }

    constexpr std::uint64_t value() const noexcept { return v_; }

private:
    std::uint64_t v_;
};

}  // namespace hpc
```

With `P` a template parameter the compiler replaces the division by a multiply-shift sequence
(Barrett or Montgomery reduction), which is roughly an order of magnitude faster than a
hardware divide.

## Implementation

The recurring implementation decision is the cutoff between a fast algorithm and the direct
one. Karatsuba's recursion has a larger constant than schoolbook multiplication, so the
crossover is empirical:

```cpp
#include <cstddef>
#include <span>
#include <vector>

namespace hpc {

// Cutoff determined by measurement on the target, not by the asymptotics.
inline constexpr std::size_t karatsuba_cutoff = 32;

std::vector<double> multiply_polynomials(std::span<const double> a,
                                         std::span<const double> b);
// Dispatches: schoolbook below the cutoff, Karatsuba above it, FFT-based
// convolution above a second, much larger cutoff.

}  // namespace hpc
```

Cutoffs are stated as named constants with the measurement that produced them recorded in
[Benchmarks](/docs/benchmarks), never as bare literals in a recursion.

## Performance considerations

Asymptotically fast algorithms lose to direct ones at small sizes and the crossover is a
property of the machine. Strassen's advantage at $n = 4096$ is real — roughly 20 percent
against a tuned `GEMM` — and it requires $\Theta(n^2)$ temporary storage and gives up the
elementwise backward stability of the direct method, replacing it with a norm-wise bound.
Whether the trade is acceptable depends on the application; in this reference it is not taken
without stating the change.

Exact arithmetic's dominant cost is operand growth. Gaussian elimination over $\mathbb{Q}$
produces entries whose bit lengths grow linearly in the elimination step, so the cost is
$\Theta(n^5)$ bit operations rather than $\Theta(n^3)$ arithmetic ones. Fraction-free
elimination (Bareiss) and modular methods both address this, the latter by keeping every
intermediate in a machine word.

Modular computations with a compile-time modulus are the case where the language contributes
directly: templating on the modulus converts a division per operation into a multiply and
shift, and the resulting kernels vectorize.

Memory traffic behaves differently from the numerical case. Exact algorithms with growing
operands are allocation-bound rather than bandwidth-bound, and the effective optimisation is
arena allocation with reuse rather than layout.

## Limitations

Exact arithmetic is unavailable for transcendental quantities: $\pi$, $e^x$ and the values of
special functions have no exact representation, and computations involving them are
approximations regardless of how the algebra is carried out. Interval arithmetic is the
rigorous alternative and costs a factor of two to four with intervals that widen with the
computation length.

Fast algorithms are numerically weaker. FFT-based convolution has error $O(u \log n)$ against
$O(un)$ for the direct method in the worst case but loses the componentwise bound; Strassen
is norm-wise stable but not componentwise stable, so small entries of the product may be
computed with no correct digits.

Arithmetic complexity ignores the cost of an operation, which for multiprecision operands
grows with operand size. Bounds in the model are correct and must be converted before they
predict running time.
