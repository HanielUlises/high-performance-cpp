## Definition

Numerical analysis is the study of the difference between the problem posed and the problem
solved.

<Definition title="The standard model">
IEEE-754 arithmetic with round-to-nearest satisfies, for $\circ \in \{+, -, \times, \div\}$
and representable $x, y$ with no overflow or underflow,
$$
\mathrm{fl}(x \circ y) = (x \circ y)(1 + \delta), \qquad |\delta| \le u,
$$
where $u$ is the unit roundoff — $2^{-24} \approx 6.0 \times 10^{-8}$ for binary32 and
$2^{-53} \approx 1.1 \times 10^{-16}$ for binary64. Square root satisfies the same bound.
</Definition>

<Definition title="Conditioning and stability">
For a problem $f$ and input $x$, the relative condition number is
$$
\kappa(f, x) = \lim_{\varepsilon \to 0} \sup_{\lVert \delta x \rVert \le \varepsilon \lVert x \rVert}
\frac{\lVert f(x + \delta x) - f(x) \rVert / \lVert f(x) \rVert}{\lVert \delta x \rVert / \lVert x \rVert}.
$$
An algorithm $\hat{f}$ is *backward stable* when for every $x$ there is a perturbed input with
$\hat{f}(x) = f(x + \delta x)$ and $\lVert \delta x \rVert = O(u)\lVert x \rVert$.
</Definition>

The two combine into the statement that governs all of numerical computation:

$$
\frac{\lVert \hat{f}(x) - f(x) \rVert}{\lVert f(x) \rVert} \lesssim \kappa(f,x)\, u.
$$

Accuracy is the product of a property of the problem and a property of the algorithm. A
backward stable algorithm on an ill-conditioned problem returns an inaccurate answer, and no
implementation effort changes this.

## Motivation

Every performance argument in this reference is conditional on producing the right answer,
and floating-point arithmetic makes "the right answer" a quantitative rather than a binary
notion. Three practical questions follow.

Which reformulations are legitimate? Reassociating a sum, using a fused multiply-add,
replacing division by reciprocal multiplication, and vectorizing a reduction all change the
computed result. Each is acceptable when its effect on the error bound is understood and
unacceptable when it is not.

Which precision suffices? Mixed-precision methods — computing a factorization in binary32 and
refining in binary64 — halve memory traffic and double vector throughput. Whether they
deliver the accuracy of the higher precision depends on the conditioning, and iterative
refinement gives the criterion.

When is a result meaningless? A computed residual smaller than $u \lVert A \rVert \lVert x
\rVert$ carries no information, and an iteration driven past that point is fitting noise.

## Formal formulation

Summation is the canonical example. For the sequential sum of $n$ terms, the computed result
satisfies

$$
\hat{s}_n = \sum_{i=1}^{n} x_i (1 + \theta_i), \qquad |\theta_i| \le \gamma_n = \frac{nu}{1 - nu},
$$

giving the forward bound

$$
\left| \hat{s}_n - \sum_i x_i \right| \le \gamma_{n-1} \sum_i |x_i|.
$$

The ratio $\sum |x_i| / |\sum x_i|$ is the condition number of summation; for terms of like
sign it is $1$ and the sum is computed to full accuracy, and for cancelling terms it is
unbounded.

Pairwise summation replaces $\gamma_{n-1}$ by $\gamma_{\lceil \log_2 n \rceil}$, and
compensated (Kahan or Neumaier) summation replaces it by $2u + O(nu^2)$, effectively
independent of $n$.

For linear systems, Gaussian elimination with partial pivoting produces $\hat{x}$ satisfying
$(A + \Delta A)\hat{x} = b$ with

$$
\lVert \Delta A \rVert_\infty \le \gamma_{3n} \rho_n \lVert A \rVert_\infty,
$$

where $\rho_n$ is the growth factor. The bound on $\rho_n$ is $2^{n-1}$ and is attained only
by contrived matrices; in practice $\rho_n$ grows like $n^{1/2}$, which is why the method is
used despite the exponential worst case.

Cancellation is a property of the problem, not of the arithmetic. Computing $x^2 - y^2$ as
written loses relative accuracy when $x \approx y$; computing it as $(x-y)(x+y)$ does not,
because the subtraction is then exact by Sterbenz's lemma when $y/2 \le x \le 2y$.

## C++ representation

Numerical properties made explicit in the interface:

```cpp
#include <cmath>
#include <concepts>
#include <limits>

namespace hpc {

template <std::floating_point T>
inline constexpr T unit_roundoff = std::numeric_limits<T>::epsilon() / T{2};

// Relative-plus-absolute comparison; an absolute tolerance alone is
// meaningless without a scale, a relative one alone fails near zero.
template <std::floating_point T>
constexpr bool approximately_equal(T x, T y, T relative, T absolute) noexcept {
    const T diff = std::abs(x - y);
    return diff <= absolute || diff <= relative * std::max(std::abs(x), std::abs(y));
}

// Sterbenz: exact when the operands are within a factor of two.
template <std::floating_point T>
constexpr bool subtraction_is_exact(T x, T y) noexcept {
    return y / T{2} <= x && x <= T{2} * y;
}

}  // namespace hpc
```

Error-free transformations, the primitives on which compensated algorithms are built:

```cpp
#include <cmath>

namespace hpc {

struct two_sum_result { double sum; double error; };

// Knuth's two-sum: sum + error is the exact sum of a and b.
constexpr two_sum_result two_sum(double a, double b) noexcept {
    const double s = a + b;
    const double bb = s - a;
    const double err = (a - (s - bb)) + (b - bb);
    return {s, err};
}

struct two_product_result { double product; double error; };

// Exact with a fused multiply-add: product + error = a · b exactly.
inline two_product_result two_product(double a, double b) noexcept {
    const double p = a * b;
    return {p, std::fma(a, b, -p)};
}

}  // namespace hpc
```

These are correct only under the standard model with round-to-nearest, and are destroyed by
compiler options permitting reassociation. Building them requires that the compiler be
prohibited from "simplifying" `(a - (s - bb))` to zero.

## Implementation

Summation, in the three forms whose bounds were given above:

```cpp
#include <cstddef>
#include <span>

namespace hpc {

// γ_{n-1} · Σ|x_i|
constexpr double naive_sum(std::span<const double> xs) noexcept {
    double s = 0.0;
    for (const double x : xs) { s += x; }
    return s;
}

// γ_{log n} · Σ|x_i|; the recursion is cut off where the call overhead
// exceeds the accuracy benefit.
constexpr double pairwise_sum(std::span<const double> xs) noexcept {
    constexpr std::size_t cutoff = 128;
    if (xs.size() <= cutoff) { return naive_sum(xs); }
    const std::size_t half = xs.size() / 2;
    return pairwise_sum(xs.first(half)) + pairwise_sum(xs.subspan(half));
}

// (2u + O(nu²)) · Σ|x_i|, at roughly four times the arithmetic.
constexpr double kahan_sum(std::span<const double> xs) noexcept {
    double s = 0.0;
    double c = 0.0;
    for (const double x : xs) {
        const double y = x - c;
        const double t = s + y;
        c = (t - s) - y;
        s = t;
    }
    return s;
}

}  // namespace hpc
```

Pairwise summation is the default in this reference: its accuracy is within a factor of
$\log n / n$ of compensated summation at the cost of the naive form, and its recursive
structure vectorizes and parallelises without further change.

## Performance considerations

Denormal operands are handled by microcode on many implementations, at a penalty of tens to
hundreds of cycles per operation. A kernel that decays into the denormal range — a damped
oscillation, a decaying exponential — can slow by an order of magnitude with no change in
instruction count. Flush-to-zero removes the penalty and changes the arithmetic; the choice
is made deliberately and recorded, not left to the ambient compiler flags.

Division and square root have latencies of ten to twenty cycles and are not pipelined at full
rate. Replacing $n$ divisions by one division and $n$ multiplications is a standard
transformation that changes the error bound by one additional rounding per element — usually
acceptable, always to be stated.

Fused multiply-add improves both speed and accuracy, computing $ab + c$ with a single
rounding. It also changes results relative to separate operations, so a routine whose
correctness depends on the absence of fusion — `two_product` above depends on its presence,
`two_sum` on the absence of reassociation — must be compiled with contraction controlled
explicitly.

Reduced precision is a bandwidth optimisation before it is an arithmetic one. Binary32 halves
memory traffic and doubles vector lane count relative to binary64; whether the accuracy
suffices is answered by $\kappa u < 1$ in the working precision, and where it does not,
iterative refinement in the higher precision recovers the accuracy at $\Theta(n^2)$ cost on
top of a $\Theta(n^3)$ factorization.

## Limitations

Backward stability is a statement about the algorithm and says nothing about accuracy for an
ill-conditioned problem. Reporting a small residual as evidence of a good solution is the
most common error in numerical software: the residual bounds the *backward* error, not the
forward one.

Error bounds are worst-case and typically pessimistic by a factor of $\sqrt{n}$, since
rounding errors behave statistically. They establish scaling, not magnitudes.

The standard model excludes overflow and underflow, so an analysis based on it is silent
about the exact circumstances in which a computation fails catastrophically. Scaling
arguments must be made separately.

Comparison of floating-point results has no tolerance-free formulation. Every equality test
in numerical code is a decision about scale, and the decision is part of the specification of
the routine.
