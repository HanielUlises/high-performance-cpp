# High Performance C++

A technical reference for modern C++, mathematical foundations, generic programming, and
performance-oriented computation.

The site is a Docusaurus 3 project in TypeScript. Content is MDX with KaTeX mathematics and
Mermaid diagrams, organised by subject rather than by language revision — C++20, C++23 and C++26
appear as compatibility metadata on the entries they affect.

## Structure

```
docs/                     Reference content, one directory per part
  modern-cpp/             Templates, concepts, constraints, compile-time programming
  mathematics/            Algebra, linear algebra, analysis, numerics, optimization
  high-performance/       Cost models, memory, layout, SIMD, parallelism, concurrency
  scientific-computing/   Factorizations, sparse, quadrature, ODEs, PDEs, AD
  formal-cpp/             Types, concepts as predicates, semantics, correctness
  examples/               Complete derivations from statement to measurement
  benchmarks/             Method, machine characterisation, recorded results
essays/                   Long-form notes (the blog plugin, remapped to /essays)
src/
  components/             Standards, Complexity, Formal, Chain — available in every MDX file
  css/custom.css          The typographic system
  pages/                  Home page and colophon
  theme/MDXComponents.tsx Global MDX component registration
sidebars.ts               One autogenerated sidebar; ordering lives with the content
docusaurus.config.ts      Site configuration
archive/                  The previous single-file site, retained for reference
```

Sidebar ordering comes from `sidebar_position` front matter and `_category_.json` files, so
adding a page never requires editing `sidebars.ts`.

## Development

```bash
npm install
npm start          # dev server at http://localhost:3000
npm run build      # production build into build/
npm run serve      # serve the production build
npm run typecheck  # tsc over the TypeScript sources
```

`npm run build` fails on any broken internal link or anchor, which is deliberate: the reference
cross-references heavily and a dangling link is a defect.

## Authoring

Every technical entry follows the same sequence: definition, motivation, formal statement, C++
representation, implementation, complexity, performance considerations, limitations, related
entries, references.

Four components are available in any MDX file without an import:

```mdx
<Standards entries={[{std: 'C++20', note: '…', paper: 'P0734R0'}]} />

<Complexity rows={[{operation: 'Reduction', time: 'Θ(n)', space: 'Θ(1)', note: '…'}]} />

<Definition title="Concept">…</Definition>   {/* also Proposition, Theorem, Law, Requirement */}

<Chain stages={[{label: 'Abstraction', detail: '…'}]} />
```

Mathematics uses `$…$` inline and `$$…$$` displayed. Section numbering is generated by CSS and
mirrored in the table of contents; do not type numbers into headings.

Editorial rules, notation and the measurement protocol are documented in `/colophon` and
`docs/conventions.mdx`.

## Deployment

`.github/workflows/deploy.yml` builds on every push to `main` and publishes to GitHub Pages.
The repository's **Settings → Pages → Source** must be set to **GitHub Actions**; the previous
configuration served the branch root directly, and leaving it there will keep serving the old
content.

`baseUrl` defaults to `/high-performance-cpp/`, matching
`https://hanielulises.github.io/high-performance-cpp/`. For a custom domain, build with
`BASE_URL=/ SITE_URL=https://example.org npm run build` and add the `CNAME` file to `static/`.
